## 一、背景：现在到底卡在哪

功能是成立的 —— 选图即生效、字体替换、更新自愈、拖拽吉祥物都能用。但两轮实测暴露的不是"功能缺"，而是**三条链路断了**：

| 断点 | 实测证据 | 用户感受 |
|---|---|---|
| **可观测性断** | 开机 45 分钟后注入全丢（`[id^=wdw]`=0），但 `--status` 四行全绿、`health` 报 `ok:true`；注入器 `stdio:'ignore'` 且不写日志 ⇒ 现场零信息 | "壁纸没了，插件坏了" |
| **状态反馈断** | 应用壁纸后卡片无选中态、「当前壁纸」恒 `—`；点卡片 250ms 内 `busy:false` 且无 toast；库计数恒等于总数 | "我点的那下生效了吗？" |
| **出口断** | 面板没有关闭按钮（只能再点吉祥物或 Esc），而右上角正是宿主窗口的关闭键；「关闭壁纸」写 `.stopped` 后连注销重登都不拉起 | "想收起点错成退出应用""关了装不回来" |

外加一个**持续性成本**问题：场景壁纸在无硬件加速环境下净耗 **≈3.2 核**（GPU 进程 425% → 移除场景后 98.6%），而 `sceneFps` 可配但面板没有任何入口。

## 二、目标与成功标准

| 目标 | 可量化标准 |
|---|---|
| G1 故障可自证 | 注入丢失时 `health` 必须报 `injection.ok:false`，且 `<dataDir>/start-ui.log` 有对应错误行；面板「系统」页可见并可一键重注入 |
| G2 状态可确认 | 应用壁纸后 1s 内卡片出现"使用中"标记，「当前壁纸」显示标题；筛选后计数与卡片数一致 |
| G3 出口明确 | 面板有 ✕；「暂停」可逆、「退出」有图形化恢复步骤，且不写 `.stopped` 也能暂停 |
| G4 成本可控 | 提供 30/24/15fps 三档 + 失焦降频；默认档在 1080p 下 GPU 进程 ≤200%（当前 425%） |
| G5 可读性有兜底 | 亮壁纸下一键调暗（0–70% 三档 + 自动），落到 `/api/mask` 持久化 |
| G6 零回退 | 每批次 `verify.js` 全绿且有新增断言；真机自更新跑通；`verify-live` 11/11 |

## 四、v1.2.4 工作包（P0，救可用性）

### WP-01 注入可观测性（本批核心）

**现状证据**：`scripts/cdp.js` 的 `ev()` 只在 `ws close/error` 时 reject，`Runtime.evaluate` 无超时；`start-ui.js` 的 15s 自愈轮询用 `polling` 单飞标志，`polling=false` 只写在 `finally`，`await ev()` 不返回则永久停摆；`companion.js:216` `spawn(..., {stdio:'ignore'})` 且 `start-ui.js` 无日志文件。

**改动**
1. `scripts/cdp.js`：`ev()`/`call()` 加 8s 超时（超时 reject，语义等同断线 → 走已有 `failAll` 路径）。
2. `scripts/start-ui.js`：轮询加失败计数；连续 3 次 → 丢弃 session 重建；连续 10 次 → 退避 60s 并把 `lastError` 写入状态。日志改 `createWriteStream(<dataDir>/start-ui.log, {flags:'a'})`，1MB 轮转保留 1 份（与 `companion.log` 同策略）。
3. `scripts/companion.js`：`spawnService` 改 `stdio: ['ignore', fd, fd]`。
4. `server/routes.js`：`health()` 增 `injection:{ok, at, attempts, lastError, pageUrl}`；新增受保护路由 `POST /api/inject`（强制 `injectAll()`）。
5. `ui/dsh-ui/panel.js`：系统页顶部状态卡（绿/红 + 「重新注入」按钮）。

**验收**：`verify.js` 新增 5 条断言（超时常量、stdio fd、health 字段、路由存在、面板按钮）；真机演练：`taskkill` 掉 start-ui → 看门狗 5s 拉起 → 面板状态卡转绿。

**风险/回滚**：8s 超时可能把"慢但会返回"的求值误判断线 → 只在 `Runtime.evaluate` 超时（非业务异常）时触发重连，且重连最多 3 次；回滚 = 还原 `cdp.js` 单文件。

### WP-02 「暂停 / 退出」拆分

**现状**：`关闭壁纸` 走 `window.confirm` → `POST /api/shutdown` → 写 `.stopped` → `companion.js:501` 检测到直接 return（注销重登不恢复）。

**改动**
1. 新增 `.paused` 标志语义：暂停 = 隐藏背景层 + 面板（`teardownAll` 的 UI 部分）+ 保留服务；`companion.js` 只在 `.stopped` 时 return，`.paused` 只影响注入。
2. 面板出口：`⏸ 暂停壁纸`（普通按钮，一键可逆）与 `⛔ 退出插件`（危险色 `--wdw-danger`，二次确认 + 三行图形化恢复步骤 + 「生成恢复快捷方式到桌面」）。
3. 吉祥物暂停态：变灰 + 点击即恢复。

**验收**：真机点暂停 → 壁纸消失、服务仍在 47851、吉祥物变灰；点吉祥物 → 恢复 <3s。`verify.js` +3 断言（`.paused` 分支、危险色 token、恢复文案）。

**风险**：`teardownAll` 拆 UI 时不慎删掉 `#wdw-rope-buddy` 会触发 15s 轮询重注入（契约 C5）→ 暂停态必须**保留吉祥物节点**只改样式。

> **实际落地（2026-10-28，与上面方案的差异）**
> - 暂停**只拆背景层**，面板与吉祥物**全部保留**（原方案要连面板一起隐藏）。理由：面板是用户唯一的恢复入口，
>   隐藏它等于把「不可逆」从退出挪到了暂停上；而保留面板就没有任何"删节点"的风险（C5 免疫）。
> - 恢复走面板「关于 → 恢复壁纸」，没有做「点吉祥物恢复」：吉祥物点击已经被「开/关面板」占用，再加一层状态判定容易误触。
> - 退出**没有**生成桌面恢复快捷方式（会在用户桌面写文件，属越界操作），改为在确认框里写明
>   「打开插件安装目录，双击 启动.cmd」+ 最后一句显式指向「取消 → 用暂停」。
> - 落地证据：`core/pause.js`（`.paused` 与 `.stopped` 分离）、`POST /api/pause`、`start-ui.js` 补注入跳过背景层、
>   `applyTheme` 自动解除暂停、面板两个按钮（危险色 `wdw-danger`）。`verify.js` +17 条（231/231）。

### WP-03 文字蒙版 UI

**现状**：`/api/mask` 可用（实测 200、`applied:true`、`GET` 返回 0），`panel.js` 全文无 mask ⇒ 接口有 UI 没有。

**改动**：系统页加「文字蒙版」三段滑块（0/25/45/65%）+「自动」（取当前壁纸平均亮度：`<0.35` 暗图 0%、亮图 40%）；值走 `POST /api/mask`，切换壁纸时重算。

**验收**：亮壁纸（山晚-三叶）下正文对比度提升可截图对比；`verify.js` +2 断言（mask 调用、自动取值函数存在）。

**风险**：不碰 `theme-css.js` 的背景规则（C1/C2 被断言钉死），只改蒙版层 opacity 一个数值。

### WP-04 发布 v1.2.4

内容 = 已修的 8 项适配（`80f91ef`）+ WP-01…03，版本号 9 处同步，`CHANGELOG` 补 1.2.4，`minSupported` 保持 1.2.1。

**验收**：CI 绿 → tag → Release 出包 → 包内自检（版本/新域 feed/新脚本/文档齐）→ 签名 + feed → 部署 → `verify-live` 11/11 → 真机自更新 1.2.3 → 1.2.4。
