# workbuddy-wallpaper 体验评审与优化建议

> 评审版本：v1.2.3（本机安装版）
> 评审方式：按真实用户路径操作（点吉祥物开面板 → 逐页签 → 应用壁纸 → 上传/更新/回滚入口），配合 DOM 实测、接口探测、进程采样。
> 评审日期：2026-10-28

## 一、结论摘要

核心功能成立：**选图 → 立即生效**、字体替换、更新检查、拖拽吉祥物、Esc 关闭都能用，鉴权与错误码也规范。问题集中在三处：

1. **可观测性为零** —— 注入掉了没人知道（health 仍 `ok`），注入器日志被 `stdio:'ignore'` 丢弃，用户和开发都没有排障入口。
2. **状态反馈缺失** —— 面板不显示"当前是哪张壁纸"（`当前壁纸 —`），应用后无提示，库计数不随筛选变化。用户无法确认"我点的那下生效了吗"。
3. **"系统"页没有系统** —— 蒙版/帧率/自启/服务状态这些最容易出事的地方全无入口，而页面本身 500px 空白。

优先级：**P0 4 项、P1 8 项、P2 9 项**。P0 里 3 项是"用户会以为插件坏了"，1 项是"点一下就能把自己卡死"。

## 三、P0（高）—— 建议在 v1.2.4 修完

### P0-1 注入静默丢失，且不会自愈；健康检查与日志都不覆盖

**问题表现**
开机 45 分钟后页面里一个 `wdw` 元素都没有，但 `--status` 四行全绿、`/api/wallpaper/health` 返回 `ok:true, version 1.2.3`。手动重启服务 8 秒恢复。

**证据**

- 实测：`document.querySelectorAll('[id^="wdw"]').length === 0`，`window.__wdwPanel === undefined`；同一时刻 `GET /api/wallpaper/health` → `ok:true`。
- 代码：`scripts/cdp.js` 的 `ev()` 只在**断线**时 reject（`ws close/error → failAll`），`Runtime.evaluate` 本身**没有任何超时**。
- 代码：`scripts/start-ui.js` 15 秒自愈轮询用 `polling` 单飞标志，`if (polling) return`；`polling = false` 只写在 `finally`，而 `finally` 要等 `await session.ev(...)` 返回才执行 ⇒ **一次不返回就永久停摆**。
- 代码：`scripts/companion.js:216` `spawn(start-ui, { stdio: 'ignore' })`，而 `start-ui.js` 全文没有写日志文件 ⇒ 首注失败、"重连失败（1/3）"这些关键日志**全部丢弃**。

**对用户的影响**
壁纸消失是"无声事故"：界面只是变回纯色，没有报错、没有提示、没有任何可点的"修复"。用户只能怀疑插件坏了并卸载。

**改进建议**

1. `ev()` 加 8s 超时（超时即 reject 并触发 `onSessionLost`），把"卡住"降级成"断线"——断线路径已有自愈。
2. 轮询加失败计数：连续 3 次失败 → 丢弃旧 session 重建；连续 10 次 → 退避到 1 分钟并在 health 暴露 `lastError`。
3. `spawnService` 改 `stdio: ['ignore', fd, fd]`（`fs.openSync(<dataDir>/start-ui.log,'a')`），带 1MB 轮转，与 `companion.log` 同策略。
4. `health` 增 `injection:{ok:boolean, at:number, attempts:number, lastError:string|null, pageUrl:string}`。
5. 面板「系统」页顶部显示该状态；`ok:false` 时显示红色条 + 「重新注入」按钮（调本地新路由 `POST /api/inject`，强制 `injectAll()`）。

### P0-2 面板永远不知道"现在用的是哪张壁纸"

**问题表现**
应用壁纸后，15 张卡片长得一模一样，没有被选中/使用中的样式；「关于」页「当前壁纸」恒显示 `—`。

**证据**

- `GET /api/wallpapers` 实际返回 `{ok:true, wallpapers:[...]}` —— **没有任何 current 字段**（`grep currentWallpaper server/ core/` 无命中）。
- 面板 `panel.js:724-725`：`st.cur = d.currentWallpaper || st.cur; st.curWe = d.weId || st.curWe;` ⇒ 永远 undefined。
- `panel.js:344` 用 `it.id === String(st.curWe)` 打 `.wdw-cur`，`:220` 早已备好 `box-shadow: inset 0 0 0 2px var(--wdw-accent)` ⇒ **样式写好了但永远触发不了**。

**对用户的影响**
"点了有没有生效"要靠肉眼比对整屏画面；同一张壁纸会重复点；换了壁纸回来找不着刚才那张。

**改进建议**
后端在 `GET /api/wallpapers`（或 health）补 `currentWallpaper`（文件名）与 `weId`（工坊 id），值取自当前主题 `theme.json`；面板卡片加"使用中"角标（不只靠描边），「关于」页显示壁纸标题。

### P0-3 亮色壁纸下全站文字不可读，而面板没有蒙版/暗度入口

**问题表现**
应用"山晚-三叶"（亮天空视频）后，左侧会话列表、中间正文、顶部标题全部变成浅灰字压亮底，几乎读不出来（截图 `_tmp/ux/21-video-applied.jpg`）。要调暗只能改代码。

**证据**

- `POST /api/mask {opacity:0..1}` 接口存在且可用（实测 200，`applied:true`，`GET /api/mask` 返回当前值 0）。
- `panel.js` 全文无 `mask` 字样 ⇒ **接口有、UI 没有**（`core/theme-css.js` 的蒙版层也在，只是没人能调）。

**对用户的影响**
壁纸越好看，工作越难受。这是壁纸类插件最容易被差评的点，且用户完全不知道怎么自救。

**改进建议**
「系统」页放「文字蒙版」三档（关 / 轻 25% / 中 45% / 强 65%）+ 细滑块，落到 `/api/mask`（服务端已持久化）；再加一个"自动"：取当前壁纸平均亮度，亮图自动 40%、暗图 0%。切换壁纸时按新图重算。

### P0-4 「关闭壁纸」对普通用户等于不可逆

**问题表现**
按钮与普通按钮同款、无危险色，文字还被挤成两行；确认框写"重新启用：再运行启动脚本"。点了之后壁纸和面板一起消失——**连"怎么点回来"的入口也一起消失**。

**证据**

- `panel.js:853` 确认框文案：「关闭壁纸？将停止壁纸服务并移除界面。重新启用：再次运行启动脚本即可。」
- `companion.js:498-501`：存在 `.stopped` 时看门狗**直接 return，不拉起**；`start-ui.js:163` 才会删它 ⇒ **注销/重启电脑都不会自动恢复**，必须手动跑 `启动.cmd`。
- 实测该按钮宽 59px、文字 2 行（Range 行盒计数法）。

**对用户的影响**
想"暂时关掉"的用户，实际执行的是"永久卸载且不知道怎么装回来"。这是最容易招致"卸不干净/装不回来"投诉的操作。

**改进建议**
拆成两个动作：

- **暂停壁纸**（默认推荐）：只隐藏背景 + 面板，服务保留，吉祥物变"已暂停"态，点一下即恢复。
- **退出插件**：危险色 + 说明"壁纸与面板会消失；恢复方式：桌面「WorkBuddy（带壁纸）」→ 设置 → 壁纸 → 启动"，确认框给出**图形化恢复步骤**，并可一键"生成恢复快捷方式到桌面"。

## 六、表现良好（保持不变）

- **401/403 带 `hint`**：`{"ok":false,"error":"missing or invalid token","hint":"受保护接口需带 X-WBWP-Token；…"}`，自助排障友好。
- **接口响应快**：`/api/wallpapers` 8ms、`/api/mask` 1ms、`/api/fonts` 1ms、`/api/update/check` 2ms（缓存命中）。
- **空态/错误态文案有出路**：离线显示"服务未连接（host）：数据加载失败，请确认壁纸服务正在运行" + 「重试」；搜索空态给"换个标签或清空搜索"。
- **Esc 关闭、拖拽吸附顶边、位置持久化**都符合直觉。
- **更新/回滚有二次确认**，且文案把"备份在 versions/ 可回滚"讲清楚了。
- **面板首屏 333ms**，页签切换 4-85ms，可接受。

## 七、未执行项（如实记录）

- **未点「关闭壁纸」**：会写 `.stopped` 导致壁纸与面板同时消失，需手动跑 `启动.cmd` 恢复；为避免打断本次评审未执行，仅通过代码与文案确认行为。
- **未做真实文件上传**：`<input type=file>` 需要系统文件选择框，只验证了接口契约与失败分支（400「仅支持 PNG/JPEG…」、服务端 10MB/80MB 上限）。
- **未在多显示器/高 DPI 环境验证**：本次为 1920×1080 @100%，Retina/125%/150% 下的面板密度未覆盖。
- **未验证注入丢失的根因**：只拿到"元素消失 + 服务健康 + 日志为空"三件事实与三处代码级风险（无超时、单飞标志、日志丢弃），未复现出确定触发条件。
