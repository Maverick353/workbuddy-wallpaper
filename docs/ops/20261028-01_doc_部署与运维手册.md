# 部署与运维手册 · workbuddy-wallpaper

> 适用版本：v1.2.2 起。目标读者：部署者、运维者、接手维护的人。
> 原则：**所有操作都能用命令复现**；凡带 ⚠️ 的步骤，做之前先备份。

---

## 1. 部署形态（先搞清楚装的是什么）

| 形态 | 入口 | 装到哪 | 适合谁 |
|---|---|---|---|
| **A. 一键安装（推荐）** | `一键安装.cmd` | `%USERPROFILE%\.workbuddy\skills\workbuddy-wallpaper` + 开机自启 vbs | 普通用户 |
| **B. 安装包** | `workbuddy-wallpaper-setup-<ver>.exe` | `%LOCALAPPDATA%\Programs\workbuddy-wallpaper` + 技能目录 | 想要"下一步下一步"的用户 |
| **C. 免安装** | 解压后 `启动.cmd` | 只跑服务，不写系统 | 只想临时看一眼 |

运行时要求：**Node ≥ 22**（WorkBuddy 自带运行时优先，无需另装）、**Windows only**、零 npm 依赖。

---

## 2. 两个进程，别混为一谈

```
WorkBuddy.exe（带 --remote-debugging-port=9222）
   └─ 壁纸服务 start-ui.js   ← 监听 127.0.0.1:47851，管壁纸/面板/更新
看门狗 companion.js          ← 每 5s 一 tick：WorkBuddy 在 → 保证服务在；WorkBuddy 没了 → 停服务
```

**"壁纸上不去"永远先分两层查**：

| 层 | 判据 | 不通意味着 |
|---|---|---|
| 服务 | `netstat -ano \| findstr :47851` 有 LISTENING | 服务没起 / 端口被占 |
| 注入通道 | `netstat -ano \| findstr :9222` 有 LISTENING | **WorkBuddy 没带调试端口启动**（最常见的假故障） |

一条命令看全：

```bash
node "%USERPROFILE%\.workbuddy\skills\workbuddy-wallpaper\scripts\companion.js" --status
```

输出 4 行：WorkBuddy / 壁纸服务 / 47851 / CDP 9222。

## 3. 启动参数与配置面

### 3.1 端口（v1.2.2 起可改）

| 方式 | 优先级 | 说明 |
|---|---|---|
| `--port <n>` | 最高 | 传给 `start-ui.js` |
| 环境变量 `WBWP_PORT` | 中 | **看门狗与服务读同一个来源**，改一处即可 |
| 默认 | 最低 | 47851 |

> ⚠️ 只改一边（例如只给 `start-ui` 传 `--port` 而不设 `WBWP_PORT`）会导致看门狗永远判"服务没起来"，
> 每 5 秒重复拉起、并反复清 `.ui.pid` —— 这是 v1.2.1 及以前的一个真实坑。

### 3.2 更新相关环境变量

| 变量 | 作用 |
|---|---|
| `WBWP_UPDATE_FEED` | 覆盖 feed 地址（调试用，只认一个源） |
| `WBWP_UPDATE_OFF=1` | 彻底关掉自动检查 |
| `WBWP_SITE_BASE` / `WBWP_SITE_QUERY` | 生成 feed 时的站点基址与 query（默认已指向现网） |

### 3.3 配置文件

| 文件 | 位置 | 说明 |
|---|---|---|
| `update.json` | 安装目录 | 随包分发的默认值（feeds / 间隔 / 备份数 / 超时） |
| `update.json` | `<数据目录>` | 用户级覆盖，字段同上；**优先级更高** |
| `.api-token` | `<数据目录>` | 受保护接口令牌（32B hex，持久化，重启不变） |

## 4. 日常运维

### 4.1 启停

```bash
# 只停服务（看门狗会在 5s 内用新代码拉回来）—— 换代码后推荐用这个
node <安装目录>/scripts/companion.js --stop-service

# 停服务 + 停看门狗（壁纸彻底消失）
node <安装目录>/scripts/companion.js --stop-watchdog

# 手动起
node <安装目录>/scripts/start-ui.js
```

### 4.2 健康检查

```bash
curl -s http://127.0.0.1:47851/api/wallpaper/health
```

关键字段：`ok`、`plugin.version`、`renderer.upToDate`、`dirs`。

### 4.3 日志

| 文件 | 位置 | 轮转 |
|---|---|---|
| `companion.log` | `<数据目录>` | 1 MB 转 `.1`，保留 1 份 |
| 服务 stdout | 无文件（由看门狗拉起时丢弃） | — |

排障顺序：`--status` → `companion.log` 末尾 → 浏览器 DevTools 里的注入元素（见第 6 节）。

### 4.4 数据目录

```
%APPDATA%\workbuddy-wallpaper\
├─ themes\            壁纸与主题（standalone/ 下是当前选中的场景或图片）
├─ we-renderer\       随包渲染器（自愈部署，版本不符会被覆盖）
├─ versions\          更新前的整包备份（保留 keepBackups=3 份）
├─ update\            下载与解压暂存（可安全删除）
├─ .api-token         受保护接口令牌
├─ .companion.lock    看门狗单实例锁（含 pid + 心跳时间戳）
└─ .ui.pid            服务 pid 记录（**只作记录，判活以端口为准**）
```

> ⚠️ `versions\` 是回滚唯一凭据。清理磁盘时**别删它**。

### 4.5 换机 / 重装：数据导出与导入

```bash
# 导出（只带用户资产：themes / mask / current-theme / we-cache / fonts-cache / 用户级 update.json）
node scripts/export.js --out D:\bak\wbwp-data.zip

# 预演（只看会写什么，不落盘）
node scripts/export.js --import D:\bak\wbwp-data.zip --dry-run

# 导入（合并覆盖，导入前自动备份到 <数据目录>/import-backup-<时间戳>/）
node scripts/export.js --import D:\bak\wbwp-data.zip
```

| 行为 | 说明 |
|---|---|
| **不带出** | `.api-token`（凭据）、`.companion.lock` / `.ui.pid` / `.companion.hb`（运行态）、`update/`（下载暂存）、`we-renderer/`（随包生成）、`*.log` |
| 导入语义 | **合并覆盖**，不是镜像 —— 绝不清空目标目录（否则会删掉令牌与备份） |
| 压缩 | stored（不压缩）zip：零依赖、跨平台稳定；壁纸本身是 webp/mp4，压缩收益低 |
| 生效 | 导入后**重启服务**一次 |

> 想彻底清空重来：手工删 `%APPDATA%\workbuddy-wallpaper\themes` 后再导入，别删整个目录（会连带删掉令牌，需重启服务重新生成）。

## 5. 更新与回滚
### 5.1 正常更新

面板 → 关于 → 「检查更新」→「立即更新」。命令行等价：

```bash
TOK=$(cat "$APPDATA/workbuddy-wallpaper/.api-token")
curl -X POST -H "x-wbwp-token: $TOK" -H "content-type: application/json" \
     -d '{"force":true}' http://127.0.0.1:47851/api/update/check
curl -X POST -H "x-wbwp-token: $TOK" -H "content-type: application/json" \
     -d '{"expectVersion":"1.2.2"}' http://127.0.0.1:47851/api/update/apply
```

> 不带 `x-wbwp-token` 一律 401 —— 这不是服务坏了。
> 从国内站下载 2.8 MB 约需 1–3 分钟，**别用 120s 超时的 curl 等**，会误判"卡死"。

### 5.2 回滚

```bash
# 列出可用备份（面板里也会显示）
ls "$APPDATA/workbuddy-wallpaper/versions"
# 回滚（受降级护栏限制：不能低于 feed 的 minSupported）
curl -X POST -H "x-wbwp-token: $TOK" -H "content-type: application/json" \
     -d '{"version":"1.2.1"}' http://127.0.0.1:47851/api/update/rollback
```

> 降级护栏是**故意的**：回滚到低于 `minSupported` 的版本，接口契约已不兼容，比留在当前版本更糟。
> 真要降级只能手工：停服务 → 用 `versions\<ver>` 覆盖安装目录 → 起服务。

### 5.3 更新失败自查顺序

1. `companion.log` / 面板错误文案里有没有 `sha256` / `签名` / `403` / `超时`
2. feed 能不能读到：`curl -s "<feed地址>"`（⚠️ 静态站每条路径都要带 `?sharecode=`）
3. 包能不能下：`curl -o /dev/null -w "%{http_code} %{size_download}" "<包地址>"`
4. 线上守门（开发侧）：`node scripts/verify-live.js`

## 6. 注入相关排障

| 现象 | 判据 | 处置 |
|---|---|---|
| 界面没有任何壁纸元素 | `cdp 9222` 未监听 | 用带 `--remote-debugging-port=9222` 的入口重启 WorkBuddy |
| 元素在、壁纸不显示 | 截图看（**别只看 DOM**） | `#wdw-bg-scene` 是 iframe，`innerHTML` 恒空；`#root` 背景本就该全透明 |
| 面板打不开 | 页面上有没有 `#wdw-rope-buddy` | 缺失时服务每 15s 会整段重注入，等一轮 |
| WorkBuddy 升级后全没了 | 同上两条 | 先查注册表自启项是否被改回（见下） |

**开机自启的真正入口是注册表**：

```
HKCU\Software\Microsoft\Windows\CurrentVersion\Run
  WorkBuddy.WorkBuddy = "D:\...\WorkBuddy.exe" --remote-debugging-port=9222
```

WorkBuddy 升级可能把它改回不带参数 —— 那就会出现"插件起来了、界面没反应"。

### 6.1 一条命令判断"界面挂上了没有"

```bash
node scripts/probe-injection.js          # 退出码 0=正常，1=不完整
node scripts/probe-injection.js --json   # 机器读
node scripts/probe-injection.js --soft   # CDP 不在时跳过（CI 用）
```

判据三条：`#wdw-*` 元素 ≥ 10、`#wdw-rope-buddy` 在、`#root` 背景已透明。
另报场景层 canvas 是否存在（`#wdw-bg-scene` 是 iframe，**innerHTML 恒为空是正常的**）。

## 7. 卸载

```bash
node <安装目录>/scripts/install.js --uninstall            # 保留用户数据
node <安装目录>/scripts/install.js --uninstall --purge-data  # 连数据一起删
```

卸载会：摘注入 → 停服务 → 停看门狗 → 撤自启 → 删安装目录 → （可选）删数据目录。

> ⚠️ 卸载器**不能有交互提问**：它由 `runhidden` 拉起，看不见窗口，`readSync(0)` 会永久阻塞
> （历史事故：用户点卸载只看到进度条卡死）。已有断言钉住这条。
