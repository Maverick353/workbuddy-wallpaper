# 页面适配覆盖矩阵与验收记录

> 目标：确认客户端内**每一个页面与主要功能入口**在**支持的目标环境**下显示与交互均正常。
> 版本：v1.2.3（本次修复后，未改版本号）
> 环境：Windows 11 家庭版 26100 64 位 · Node 22.22.2 · 1920×1080 · 单屏 · 键鼠
> 方法：CDP 真实视口模拟（`Emulation.setDeviceMetricsOverride`）+ 真实鼠标/键盘事件 + DOM 度量，非目测。

## 一、支持的目标环境（本项目的口径）

| 维度 | 支持范围 | 依据 |
|---|---|---|
| 操作系统 | Windows 10 1809+ / Windows 11 x64 | Inno 安装器最低要求；脚本只用 `tasklist` / `netstat` / `%APPDATA%` 等通用能力 |
| 运行时 | Node ≥ 22（宿主自带） | `core/proc.js`、`cdp.js` 用全局 `WebSocket` |
| 宿主 | WorkBuddy 5.9.x（Electron / Chromium ≥ 120） | `@media (prefers-reduced-motion)`、`color-mix()`、`aspect-ratio` 都需新版 Chromium |
| 窗口（CSS px） | **≥ 720 × 420** | ≤720 走贴边全宽布局；<420 高时面板内可滚动，不裁切 |
| 显示缩放（DPI） | 100% / 125% / 150% / 175% / **200%** | 1920 屏 @100%–200% ⇒ CSS 1920×1032 → 960×516 |
| 输入 | 鼠标 + 键盘（Esc / Tab） | 无触控适配目标（桌面端） |

> 本机只验证了 Win11。**Win10 无法在本机切换**，风险点与结论见第六节。

## 五、本轮修复（均为适配缺陷，不涉业务逻辑）

| # | 缺陷（修复前） | 复现范围 | 根因 | 修法 |
|---|---|---|---|---|
| 1 | 面板压住宿主窗口的最小化/最大化/关闭按钮 | **全部 7 组环境** | 面板 `top:12px`，宿主窗口控制按钮占 y 0–30 | 面板改 `top:34px` / `height:calc(100vh - 46px)`；≤720 的贴边布局同步 |
| 2 | `上传` `扫描` `关闭壁纸` 被压成竖排两行 | **全部 7 组** | `.p-btn` 无 `white-space`，作为 flex 子项时中文 `min-content` 退化为单字宽 | `.p-btn{white-space:nowrap;flex:0 0 auto}` |
| 3 | `立绘模式` 状态标签折两行 | **全部 7 组** | `.p-hint` 在 `.p-row` 里可压到 36px | 短标签加 `.p-tag{flex:0 0 auto;white-space:nowrap}` |
| 4 | 收藏星标 18×18、色块 20×20（点击目标偏小） | 全部 | 尺寸硬编码 | 星标 / 删除 22×22，色块 22×22（`.p-swatches` 宽度同步 132→146） |
| 5 | 面板**没有关闭按钮** | 全部 | 头部只有标题 | 头部加 ✕（`data-act="close"`），`WIRE_VER` 2→3 强制重建 |
| 6 | 键盘焦点不可见 | 全部 | 无 `:focus-visible` 规则 | 按钮/输入/可聚焦元素加 2px 强调色描边 |
| 7 | 库计数恒等于总数（场景 14/视频 1/图片 0 都显示 15 项） | 全部 | `repoCountText()` 返回 `items.length` | 改 `filter(passFilter).length` |
| 8 | 「当前壁纸」恒显示 `—`，WE 卡片无"使用中"高亮 | 全部 | `/api/wallpapers` 不返回 `weId`/标题（WE 用 `background.mp4|.pkg`，无 webp 可比对） | `applyWe` 落盘 `weTitle`；`listWallpapers` 回传 `weId` + `currentTitle`；面板优先显示 `curTitle` |

> 第 7、8 项不是样式问题，是**页面显示不出正确状态**，属于"显示是否正常"的范围，故一并修。
> 第 8 项修复后实测：`/api/wallpapers` → `{weId:"1976723593", currentTitle:"Windows 4K dark theme"}`，面板「关于」显示该标题，卡片出现强调色描边。

**回归锁定**：`verify.js` 新增 7 条适配钉（185 → **192**），把上述 1/2/3/4/5/7/8 的结构前提钉死，防止再犯。`verify-apply-real.js` 真包 **54/54** 仍通过。

## 六、未覆盖项与残余风险（如实记录）

| 项 | 状态 | 说明 / 建议 |
|---|---|---|
| Windows 10 实机 | **未验证** | 本机仅 Win11 26100。代码只用 `tasklist`/`netstat`/`%APPDATA%`/`%LOCALAPPDATA%`，Win10 1809+ 均有；真实风险在 Inno 安装向导与 `runhidden` 行为，需在 Win10 上跑一次 `setup.exe` 冒烟 |
| 多显示器 / 混合 DPI | **未验证** | 面板用 `position:fixed` + `100vh`，跨屏拖动时 Chromium 会按新屏 DPI 重排；理论可行但未实测 |
| 触控 / 触控板手势 | 不在支持目标 | 星标 22px 仍小于触控推荐的 44px；若将来支持触屏需整体放大 |
| 真实 4K（3840×2160 @150%） | 未实测 | 用 1536×826 @125% 等价替代；差异仅在物理像素密度，CSS 行为一致 |
| 宿主窗口控制按钮形态 | 依赖宿主版本 | 面板 `top:34px` 是按 WorkBuddy 5.9.x 的 30px 标题栏定的；宿主若改高度需同步 |
| WorkDaddy 悬浮球（`wbs-fab`） | 环境干扰项 | 其 `z-index:2147483647`，固定在右边缘（x≈1272，宽 41）。当前与面板右边界（1268）**不重叠**；若面板加宽会撞上，需注意 |

## 七、复跑方式

```bash
# 布局矩阵（每个组合扫 7 个页面）
node _tmp/audit-pages.js <宽> <高> <dpr>      # 例：node _tmp/audit-pages.js 960 516 2

# 交互验证（关闭按钮 / 页签 / 滚轮 / 键盘焦点）
node _tmp/audit-interact.js <宽> <高> <dpr>

# 断言
node scripts/verify.js            # 192 / 192
node scripts/verify-apply-real.js # 54 / 54
```

> 探针脚本在仓库外的 `_tmp/`（按目录约定：临时探针不进仓库）。若要长期复用，建议移入 `scripts/probe-layout.js` 并接入 CI 的 Windows 步骤。
