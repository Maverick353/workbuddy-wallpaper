# 自我进化机制（evolve）

> 落地版本：v1.2.3 工作副本（未发版）
> 代码：`core/evolve/`（6 模块）+ `scripts/evolve.js`（CLI）+ `evolve.config.json`（策略）
> 断言：`verify.js` 新增 11 条（192 → **203**），全部离线可跑
> 一句话：**机器负责找料和起草，人负责拍板；代码永不自动改。**

---

## 一、为什么是"半自动"而不是"全自动"

先把边界说清，否则后面所有设计都是空话。

搜索结果与项目实际之间**必然存在语义 gap**：一条 "Electron 45 升级了 Chromium 156" 对我们是"要复测注入时序"，但任何规则都写不出"改哪一行"。让机器自动改代码，产出的只会是似是而非的 diff，且每一条都要人再读一遍才能判断 —— 比人直接写更慢、更危险。

所以本机制的分工是：

| 环节 | 谁做 | 为什么 |
|---|---|---|
| 找料（联网、筛选、去重、打分） | 机器 | 确定性规则，可复现、可断言 |
| 起草（摘要 + 建议动作 + 记录进 backlog） | 机器 | 模板化，不会说错话 |
| **改代码 / 改配置** | **人** | 语义判断，机器不做 |
| 验证 / 回滚 | 机器 | 有明确判据 |

它能自动改的**只有一类**：`append-doc` 到 `docs/evolve/backlog.md`（把候选记成待办）。这是"记录"不是"决策"。

## 二、架构

```
scripts/evolve.js             CLI：status / run / list / show / apply / rollback / sources
evolve.config.json            策略：目标、触发、数据源、打分权重、写入边界、预算
core/evolve/
  index.js    编排：判到期 → 采集 → 评分 → 出提案（run 永不改代码）
  sources.js  采集：github-releases / github-issues / hn / rss / file，含代理隧道 + 缓存兜底
  rank.js     筛选：时间窗 → 打分 → 分类 → 去重（纯函数，可单测）
  plan.js     起草：markdown 提案 + ops（append-doc）
  apply.js    落盘：白名单/黑名单/预算/备份/自动回滚（唯一会写文件的地方）
  validate.js 验证：node --check + verify.js（且断言数不得下降）
  journal.js  记账：journal.jsonl（追加式）+ state.json + cache/ + backup/
```

运行态全在 `.evolve/`（已 gitignore）；**提案本体**在 `docs/evolve/proposals/`（入库，可 review、可对比多轮）。

## 三、触发条件

`due()` 纯读本地状态，不发请求。任一成立即到期，靠前的优先级更高：

| 触发 | 条件 | 默认 | 语义 |
|---|---|---|---|
| `verify-failure` | 上次 `verify.js` 是红的（state 里 `lastVerifyOk=false`） | 开 | **先修再采集**，别在红的基线上做决定 |
| `manual` | `--force` | — | 人工随时 |
| `version-change` | `package.json` 版本 ≠ state 里记录的版本 | 开 | 发版后必须复评（新版本可能带来新问题） |
| `schedule` | 距上次 run ≥ `scheduleHours` | 24h | 日检：只看仓库动态（releases + issues） |
| `deep-due` | 距上次深检 ≥ `deepCheckHours` | 168h | 周检：加上 HN / 官方博客等最佳实践源 |
| `issue-surge` | 最近 `windowDays` 天 issue 数 ≥ `min` | 7 天 / 5 条 | 采集后才判定，写进提案抬头 |
| `stale-apply` | 距上次成功 apply ≥ `staleApplyDays` | 90 天 | 提醒"机制本身是否还有效" |

调用面：

- 手动：`node scripts/evolve.js run`（未到期会以退出码 2 结束，不产生噪音）
- 定时：`.github/workflows/evolve.yml`，每周一 03:00 UTC 深检 → 开 issue（**不 push 代码**）
- 本地定时（可选）：交给宿主自动化跑 `npm run evolve:run`，同一套到期判断

## 四、搜索范围与频率

**范围**由 `evolve.config.json` 的 `sources[]` 决定，只有这五类适配器：

| 类型 | 取什么 | 例 |
|---|---|---|
| `github-releases` | 仓库发版说明 | 自家发版（**会被剔除**，见下） |
| `github-issues` | 最近 `windowDays` 的 issue = 真实用户反馈 | 自家仓库 |
| `hn` | Hacker News 故事（技术方案 / 最佳实践） | `electron performance` |
| `rss` | 任意官方博客 RSS | Electron 官方博客 |
| `file` | 本地 JSON（离线演练 / 断言用，不联网） | CI |

**频率**：日检 24h（2 个请求）、深检 168h（5 个请求）、单轮 `maxRequests` 上限 20，单请求 8s 超时、2MB 上限。

**缓存与降级**：每个源成功后写 `.evolve/cache/<源>.json`。下一轮取不到实时数据时用缓存兜底并标记 `fromCache`，提案里明写"N 个源本轮未取到实时数据，结论只代表已知信息"。**单源失败永不拖垮整轮。**

> 本机 `curl`/`git` 都走本地代理，而 Node 的 https 不认 `HTTPS_PROXY`。`sources.js` 因此手写了 CONNECT 隧道（`tunnel()`），否则本机永远采不到 GitHub —— 这是实测踩出来的。

## 五、结果筛选标准（严格按此顺序）

1. **时间窗**：`ageDays > windowDays`（默认 180）丢弃；**安全类不受限**（历史公告仍要看）。无时间戳的保留但不得时效加分。
2. **信息量**：正文 < 12 字且标题 < 10 字 → 丢弃（标题党/空条目）。
3. **自家发版剔除**：`sourceKind=repo-release` 且属于 `self` 仓库 → 丢弃（含 CVE/security 字样才保留）。理由：已发出去的版本我们本来就知道，进候选只会淹没真信号。
4. **打分**（`rank.js`，确定性规则）：
   - 命中目标关键词：标题 **+3×权重**、正文 **+1×权重**（6 个目标，权重 0.8–1.5）
   - 来源权重：`repo-issue 5 / repo-release 4 / hn 2 / rss 2 / file 1`
   - 时效：≤30 天 +2，≤90 天 +1
   - 安全类 +4；label 命中 `bug/regression/security` 再 +3/+2
   - 无链接 -1
5. **阈值**：`score ≥ minScore`（默认 6）才进提案；`≥ highScore`（12）标"高优先"。相关度 0–100 = `score/25×100`（截顶）。
6. **分类**：`security → compat → perf → bug → ux → doc → release → feature → other`，每条候选只落一类，决定"建议动作"模板。
7. **去重**：同 URL 直接合并；标题按**中文二元组 + 英文词**算 Jaccard，> 0.75 视为同一件事，保留高分那条并记 `dupes`。

## 六、优化决策流程

```
① 到期？           due() 五项判据，未到期直接退出（码 2，不打扰）
② 量基线           verify.js 跑一次，记 lastAssertions / lastVerifyOk
③ 采集             sources.collect()，失败用缓存，状态全量记录
④ 筛选打分         rank() → kept / dropped / stats
⑤ 起草             plan.render() → 提案 md + ops（仅 append-doc）
⑥ 落盘             docs/evolve/proposals/<id>.md + .json（入库）
⑦ 通知             CI 开 issue / 本地看 CLI 输出
─────────────── 以下必须有人参与 ───────────────
⑧ 读提案           人判断"这条和我有关吗"
⑨ 试运行           evolve apply <id> --dry-run   （打印 diff，不写盘）
⑩ 应用             evolve apply <id>             （自动备份 + 应用 + 跑断言）
⑪ 提交/回滚        断言绿 → 人 commit；红 → 自动回滚，或 evolve rollback <id>
```

第 ⑧ 步是**唯一不可自动化**的一步，也是这条链路的止损点。

## 七、权限边界

**能写什么**（`apply.allowedPrefixes`，默认）：`docs/`、`CHANGELOG.md`、`README.md`。

**碰不得什么**（硬拒，代码里写死）：

| 拒绝项 | 原因 |
|---|---|
| `.git/` `_backup/` `_rollback/` `.evolve/` | 版本控制与凭据本体 |
| `installer/` `landing/` `landing-site/` | 发布链路，改错等于发错包 |
| `dist/` `node_modules/` `_tmp/` | 构建产物与临时区 |
| `*.pem` `*.key` `*.p12` `*.pfx` `.api-token` | 密钥 |
| `..`、绝对路径、盘符路径 | 路径穿越 |

**代码与配置**（`core/` `ui/` `server/` `scripts/` 等）：**不在白名单，永不自动写**。`--allow-code` 只对白名单内的 `*.js/*.json`（如 `docs/` 下的脚本）开一个小口，且要求人工显式加参数。

**其它硬约束**：

- 应用前 `git status` 必须干净（否则备份/还原会盖掉你未提交的改动）；
- 单次 ≤ 3 个文件 / ≤ 120 行（`maxFiles` / `maxLines`）；
- `replace-exact` 要求原文**恰好出现 1 次**，否则直接抛错（不做模糊匹配）；
- 不装依赖、不跑网络写操作、不杀进程、不改配置。

## 八、验证方式

应用后自动跑（`validate.runAll`）：

| 检查 | 判据 |
|---|---|
| `node --check` | 所有改动的 `.js` 语法通过 |
| `verify.js` | 失败数 = 0，**且通过数 ≥ 基线**（防"删断言让它变绿"）|
| 预算复核 | 文件数/行数在 `maxFiles`/`maxLines` 内（在 precheck 已卡，这里复核）|

任一不过 → 立即回滚并记 `apply-failed`。

`verify.js` 自身新增 11 条 evolve 断言（离线、不联网），覆盖：配置完整性、`classifyPath` 的四类边界（白名单/穿越/代码/密钥）、`rank` 的 own-release 剔除与 compat 识别、`buildOps` 只产 append-doc、越界目标在 dryRun 前就被拒。

## 九、回滚机制

- **备份**：应用前把涉及的每个文件逐字节复制到 `.evolve/backup/<提案id>/`，写 `manifest.json`（含 `existed:false` 标记"这个文件是本次新建的"）。
- **自动回滚**：写入抛错或断言不过 → 立即用备份还原；新建的文件被删除。返回 `rolledBack:true`。
- **手动回滚**：`node scripts/evolve.js rollback <提案id>`，按 manifest 逐个 restored / deleted。
- **记账**：`journal.jsonl` 追加记录 `apply-start / apply-ok / apply-failed / rollback / apply-rejected / apply-dryrun`，含文件、行数、检查结果、备份路径。任何一次应用都能复盘。

```bash
node scripts/evolve.js apply EV-20261028-0956 --dry-run   # 先看
node scripts/evolve.js apply EV-20261028-0956             # 真应用（失败自动回滚）
node scripts/evolve.js rollback EV-20261028-0956          # 手工还原
```

## 十、用法速查

```bash
node scripts/evolve.js status            # 到期了吗 / 上次跑过什么 / 断言基线 / 备份数
node scripts/evolve.js run --force       # 日检（只出提案）
node scripts/evolve.js run --force --tier deep   # 深检（含 HN / RSS）
node scripts/evolve.js run --offline     # 完全离线（只有缓存也跑得通）
node scripts/evolve.js list              # 历史提案
node scripts/evolve.js show <id>         # 打印全文
node scripts/evolve.js sources --deep    # 各源健康度（真打一次请求）
```

## 十一、已知边界与后续

| 项 | 现状 |
|---|---|
| 摘要质量 | 抽取式（关键词密度挑句），不是理解式；长文只能给个方向，最后仍需人读原文 |
| 中文分词 | 用二元组近似，英文按词；跨语言同义（"卡顿" vs "stutter"）靠关键词表兜，表要人维护 |
| 无 LLM | 刻意不做：本机无稳定 API、结果不可复现、CI 里跑不了。将来若接入，只能用于"起草"，不能给写权限 |
| 面板入口 | 目前纯 CLI。后续可在「系统」页展示"最近提案 + 待审批数"，但**应用动作仍留在命令行**（避免误点） |
| 频率上限 | GitHub 匿名 API 60 次/小时；当前日检 2 请求 + 深检 5 请求，远低于上限，不必加 token |
